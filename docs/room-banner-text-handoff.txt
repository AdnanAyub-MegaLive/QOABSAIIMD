POST /api/v1/audio-rooms/{roomId}/banners
Alias: /api/audio-rooms/{roomId}/banners (same methods and access checks).
Same Bearer session, image, packageId, settingsRevision and requestId /
Idempotency-Key as before. Add multipart:
  name: required, 1–60 Unicode characters, one line
  description: optional string, at most 200 whitespace-separated words,
               2,000 Unicode characters and 10 line breaks
Both fields are cleaned of control/invisible characters and checked against
the current prohibited-word policy before charging. No links in either field,
matching the existing public Country Chat policy. Lengths are never truncated.
For retries, retain the original text, image, settings revision and request ID.
Changing text on an upload retry returns IDEMPOTENCY_CONFLICT.

Pending owner edits:
PATCH /api/v1/audio-rooms/{roomId}/banners
Content-Type: application/json
{ "action":"EDIT_TEXT", "bannerId":"...", "name":"Room news",
  "description":"Full description" }
Send both text fields. Omit description or send "" to clear it.
Returns {success:true,data:{banner:{...}}}.
Edits preserve createdAt, position, package, price and original request result
identity. No further charge. Live/rejected/expired/deleted banners reject edits.
Existing PATCH {bannerIds:[...]} reorder contract remains unchanged.

Admin review displays the submitted text and allows saving corrected or blank
text for pending banners, then approval using the existing Approve button.
Live banner text cannot be edited even by an admin.

All owner/public banner DTOs now include name and description, including
room join roomBanners and audio-room:banners-changed snapshots.
Treat both as plain text; never render as HTML.
On tap, show image, name if nonempty, and full description if nonempty.
Build the owner word counter using trim().split(/\s+/), with zero for empty.
Refresh owner data after editing to display the normalized text.
Admin-approved text is authoritative.
